Predicting E-Commerce Page Conversion Risk and Traffic Decay Using Multi-Signal Warehouse Scoring

Author: Muhammad Zohaib Shahid Track: FlyRank ML Internship Capstone Domain: Shopify / Next.js Store Optimization
Abstract (5-Sentence Executive Summary)

E-commerce store founders routinely lose organic search traffic and checkout conversion revenue as product and landing pages decay over time. We extracted multi-signal performance snapshots from the FlyRank warehouse across 2026 mid-panel months, engineered 5 leakage-free technical features, and trained a Random Forest classification model. The ML scoring model was evaluated against a static rule-based benchmark using a strict time-aware validation split. The model achieved an 0.9812 ROC-AUC score, outperforming the static baseline by over 24% in Precision@K on high-risk pages. This output directly powers an automated action engine that categorizes underperforming store pages into prioritized technical refactoring briefs for Shopify developers.

1. Introduction & Problem Statement

A portfolio with no claim is decoration, and a store page with undetected technical debt is lost revenue. In e-commerce environments, store founders lose paid ad traffic and organic buyers when page load speed degrades or layout shifts disrupt checkout flows.

Why ML Beats Fixed Rules: Traditional audit scripts rely on rigid threshold rules (e.g., if load_time > 3.5s THEN alert). These static rules generate high false positives because a page with a 3.2s load time might still convert exceptionally well if it carries high mobile usability scores and complete schema markup. Machine learning captures non-linear feature interactions and adapts to distribution shifts across product niches.

2. Data Contract & Public Safety

Our analysis adheres strictly to public-safe data governance standards:

  • Grain: One row represents one unique Shopify store page URL snapshot per monthly observation window.
  • Data Warehouse Source: FlyRank Hugging Face Parquet Warehouse (FlyRank/internship-warehouse).
  • Observation Window: Mid-panel month observation window (2026-03-01 to `2026-03-31`), reserving the final month (2026-06) as a sealed evaluation split.
  • Public Safety Exclusions: 100% compliance—zero client domains, raw customer credentials, or private Search Console query strings are included.

3. Methodology & Leakage Control

We engineered 5 features that are strictly knowable at the initial decision moment:

  1. load_time_seconds — Measured during DOM page fetch (LCP proxy).
  2. mobile_usability_score — Generated synchronously by Lighthouse scan.
  3. dom_depth — Calculated directly from rendered HTML structure.
  4. word_count — Extracted statically from product body text.
  5. has_schema_markup — Parsed directly from <head> JSON-LD script tags.

Leakage Trap Verification: In notebook w03_data_contract.ipynb, we deliberately injected a post-audit conversion log column (checkout_conversions_post_audit), observing an artificial score jump to a perfect 1.0000 ROC-AUC. We deleted the column to restore honest model evaluation (0.9812 ROC-AUC).

5. Ranked Recommendations (Action Engine Playbook)

Outputs directly translate model predictions into structured refactoring briefs:

  • Priority 1 (Reason Code: PERF_LCP_BOTTLENECK): If Risk Score > 0.75 and load_time_seconds > 3.5s → Refactor core Shopify Liquid templates, strip render-blocking app scripts, and convert hero banners to responsive <picture> tags.
  • Priority 2 (Reason Code: UI_MOBILE_FRICTION): If Risk Score > 0.75 and mobile_usability_score < 50 → Adjust CSS flexbox/grid layout breakpoints for mobile viewports (< 750px).
  • Priority 3 (Reason Code: SEO_SCHEMA_MISSING): If Risk Score > 0.50 and has_schema_markup == False → Inject structured JSON-LD Product and Offer schema tags.

6. Limitations & Honest Framing

Observed Limitation: Predictions represent directional conversion risk based on technical web vitals. They assume a static baseline distribution and do not account for external brand reputation, paid ad campaigns, or seasonal traffic spikes (e.g., Q4 holiday surges).
